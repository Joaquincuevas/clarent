**Classic decision, optimization and engineering methods — as tools that compute, not prompts that sound smart.**

Military doctrine, Toyota's shop floor, Soviet inventors' algorithms, NASA safety engineering: decades of method for finding root causes, attacking plans and estimating honestly. Clarent turns them into small, auditable tools for developers and their coding agents: Claude Code skills, a CLI, and (soon) hooks, MCP tools and GitHub Actions.

> **Status: pre-release (v0.1).** Two methods are implemented end-to-end (`ach`, 23 tests; `triz-matrix`, 38 tests). Eight more are specified in [`research/product-spec.md`](research/product-spec.md); the rest of the plan is in [`research/roadmap.md`](research/roadmap.md). Nothing here claims to make your agent fix more bugs — see [What we do not claim](#what-we-do-not-claim).

## Why another methods repo?

Collections of "thinking frameworks as prompts" already exist (the biggest we found has ~1.7k stars; see [`research/novelty.md`](research/novelty.md)). They give an agent a checklist. Clarent's rule is stricter: **every method must have a deterministic core** — something the code computes or rejects with no LLM involved — plus evidence discipline:

- the agent **proposes**, the engine **scores, validates and can say no**;
- every observed fact needs a `ref` (the command, `file:line` or log that produced it);
- reports say what they are: an ACH score is a *ranking of inconsistencies*, never a probability.

## Demo

Everything below is the real output of the command shown, on the synthetic examples shipped in [`methods/`](methods/). The files in [`docs/demo/`](docs/demo/) hold the complete outputs and are regenerated by `python tools/gen_demo.py` (CI fails if they drift).

### `ach` — debugging with competing hypotheses

A test, `test_checkout_total`, fails about 1 run in 8 on CI. Five rival causes and a catch-all, five pieces of evidence, each rated against *every* hypothesis:

```console
$ clarent ach score methods/ach/examples/flaky-test.json
```

Excerpt (the full report also has the evidence matrix, diagnosticity, sensitivity and warnings — [`docs/demo/ach-score.md`](docs/demo/ach-score.md)):

```markdown
## Conclusion

- Tie: several hypotheses share the lowest inconsistency score.
- Leader(s): H1, H5 (margin over the next: 21)
- This is a ranking of inconsistencies, **not a probability**.

## Hypothesis ranking (lower inconsistency = better)

| # | Hypothesis | Inconsistency | State | Contradicted by |
|---|-----------|---------------:|--------|-----------------|
| 1 | **H1** Race condition between xdist workers on a session-scoped fixture | 0 | alive | — |
| 1 | **H5** Leftover DB state from another test that ran earlier on the same worker | 0 | alive | — |
| 1 | **H6** Something else I am not considering | 0 | catch-all | — |
| 2 | **H2** Clock/timezone dependence (datetime.now near a day boundary) | 21 | refuted | E2, E1 |
| 3 | **H3** Real, unmocked network call that sometimes answers slowly or errors | 27 | refuted | E4, E1 |
| 4 | **H4** Non-deterministic set/dict ordering (PYTHONHASHSEED) changes a float sum | 33 | refuted | E3, E1, E5 |
```

Clock, network and hash-seed causes are refuted by cited evidence; two causes tie. Which single experiment separates them?

```console
$ clarent ach next methods/ach/examples/flaky-test.json
T1  priority=36.0  for=H5  against=H1
    Reproducing serially with the same random order as the failure (pytest-randomly --randomly-seed=<seed of run #8812>) also fails
T2  priority=9.0  for=H1  against=-
    Changing the fixture from scope=session to scope=function removes the failures in 200 runs with '-n 4'
```

### `triz-matrix` — a design trade-off, resolved against the 1973 table

"Make `/search` faster without making the system harder to run":

```console
$ clarent triz-matrix lookup latency "Device complexity"
```

```markdown
# TRIZ contradiction: improve «Speed» without worsening «Device complexity»

- **Improving:** 9. Speed — _software reading: latency, response time or throughput of an operation_
- **Worsening:** 36. Device complexity — _software reading: system complexity: number of components, dependencies, code paths_
- «latency» was interpreted as parameter 9 (Speed) by software-reading match

> Cell verified: the consensus of 4 independent transcriptions equals the Altshuller Foundation 1973 table.

## Principles (in the order the matrix lists them)

| # | Principle | What it means | Software example |
|--:|---|---|---|
| 10 | **Preliminary action** | Carry out the required change, fully or partly, before it is needed. | Precompute results; warm caches; ahead-of-time compilation; pre-pulled images and pre-provisioned environments. |
| 28 | **Mechanics substitution** | Replace the way the parts interact with a different kind of channel or field. | Replace polling with events or webhooks; replace manual review with automated static analysis. |
| 4 | **Asymmetry** | Replace a symmetrical form with an asymmetrical one, or increase existing asymmetry. | Separate read and write paths (CQRS); one writer with many read replicas; asymmetric roles in a protocol. |
| 34 | **Discarding and recovering** | Let parts that have done their job go away or change during operation, and restore used-up parts straight away. | Garbage collection; cache eviction and TTLs; log rotation; automatic cleanup of ephemeral environments; compaction. |
```

The report goes on with a reminder that principles are prompts for ideas, not solutions, and the reverse cell. `triz-matrix analyze methods/triz-matrix/examples/search-api.json` does the same for several contradictions at once and ranks the principles that recur ([`docs/demo/triz-analyze.md`](docs/demo/triz-analyze.md)). Ambiguous names are rejected with the candidates listed, never guessed.

### In Claude Code

```text
/clarent-methods:ach test_checkout_total fails ~1 in 8 CI runs
/clarent-methods:triz-matrix make /search faster without making it harder to run
```

The skills are manual-only (`disable-model-invocation`), so they cost no context until you call them. `ach` makes the agent list rival causes first, gather evidence by running commands, rate each item against *all* hypotheses, and re-score until one explanation survives or the diagnosis is declared unresolved.

## What we do not claim

- That a skill makes an agent solve more tasks. gstack (one of the biggest repos in this space) publishes a null result on its own bug-fixing benchmark in its README; we will publish ours, null or not.
- That the numbers are Heuer's, Shewhart's or Goldratt's. Where a constant is ours (weights, thresholds) the method card says so.
- That the catalog's sources are all verified. Each one carries its verification level.
- That the TRIZ matrix data has a clean chain of title. Its licenses and gaps are written down in [`DATA_LICENSE.md`](methods/triz-matrix/clarent_triz/data/DATA_LICENSE.md); 29 of its 1 248 cells are contested between transcriptions, and you can supply your own matrix with `--data`.
- That the demos are real incidents. The examples are synthetic and labelled so.
- That the specified methods exist. `redteam`, `spc`, `intent`, `rcf`, `kt`, `gate`, `fta` and `hazop` are specifications; nothing is promised about when they ship.
- That it works in agents other than Claude Code. The plugin is validated with `claude plugin validate`; Cursor, Codex and others have not been tested.
- That the ranking of methods is a measurement, or that its "no existing repo" findings are proof of absence: they are lower bounds from GitHub search.
